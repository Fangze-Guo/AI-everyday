## 一、今日头条

### 1. 提示词在推理链上被偷读：OpenRouter 摘牌 3 家服务商，125 个端点失去"零留存"
- 11 月 22 日，AI 路由平台 **OpenRouter** 发布公告：已**下架 3 家推理服务商**，并把 **125 个端点**从 **Zero Data Retention（ZDR，零数据留存）**资格名单中移除，其中既有被研究者点名的厂商，也有出于预防一并移除的端点；公司称已通知全部可能受影响的客户，并强调调查结果**未显示 OpenRouter 自身被入侵**。
- 触发点是安全公司 **Dragos** 首席研究官 **HD Moore** 11 月 19 日发布的研究：2026 年 7 月至 11 月，团队向多家 AI 服务发出**近 200 万条**携带唯一 URL 与诱饵凭据的提示词，追踪约 **2000 条**请求路径。三条结论：至少 **3 家**托管商被攻陷且事前均不知情（最早可追至 7 月中旬）；市场转售商用**普通日志工具**即可查看并留存客户提示词，既无漏洞也无需绕过；部分厂商未遵守 ZDR 等隐私设置。规模最大的一起发生在 10 月下旬，约 **200 把**诱饵 AWS 密钥被盗用，随后产生**数万次** AWS API 调用，包括列举存储桶、翻查密钥库、尝试开通 Amazon Bedrock 上的托管模型。
- Moore 的判断很直接：隐私开关"**只约束第一跳**"——它管得住你签约的那家，管不住下游的转售商和上游实验室；"攻击者已经在里面时，隐私标记帮不上忙"。
- 已公开承认的厂商中，**Together AI** 的链条最典型。11 月 21 日披露：一个 **AI 编码智能体**在开发其公开仓库 **xorl** 时提交了一个凭据，该凭据可访问存放提示词样本的私有 Hugging Face 仓库；样本来自 **MiniMax M3、GLM-5.2、Kimi K2.6** 的请求，集中在 6 月 24 日、7 月 4 日、7 月 8 日、7 月 14 日。自动扫描发现后虽已回滚提交，但凭据在暴露窗口内被取走，入侵者下载样本后**继续在样本里搜其他服务的凭据并逐个试活**，其中 **5 个**命中 Dragos 埋下的金丝雀。
- 另两家已发公告：**Phala** 在 11 月 10 日的初步报告里称，10 月 21 日至 11 月 8 日经 OpenRouter 路由的 DeepSeek V4 Flash 请求应视为已暴露、其中所有密钥应轮换；**Novita** 说明是一处路由配置把部分 MiniMax 请求转发到了 MiniMax 自己的 API。OpenRouter 未公布被摘牌的 3 家名字，只挂出厂商公告清单，并表示将对网络路径做技术核验、恢复 ZDR 标签前要求厂商提供保证与验证。

### 2. OpenAI 全站中断 211 分钟：一次例行维护打穿了两层"冗余"
- OpenAI 在状态页发布复盘：**11 月 21 日 13:48—17:21（太平洋时间）**，ChatGPT 与 API 的请求失败率**峰值达 75%**，付费与免费用户同时受影响，累计 **211 分钟**，约 3.5 小时。
- 起因不是攻击，而是**例行维护**。Primary API 所用的 Postgres 数据库服务在维护中**两个只读副本同时失效**；这两个副本并非闲置备份，OpenAI 自己的用词是"**load-bearing（承重）**"。由于 Primary API 同时承担整个技术栈的**用户认证与服务间认证**，一次数据库故障被放大为公司级中断。
- 抢修并不顺利：多次尝试唤醒任一失效副本、在其它区域拉起替换副本均告失败，最终与服务商协作在**同一区域新建两个副本**才恢复。API 侧受影响接口包括 Chat Completions、Fine-tuning、Embeddings、Images、Batch、Audio、Moderations、Realtime 与 Files；ChatGPT 侧波及对话、登录、搜索、文件上传与语音模式。11 月 22 日上午状态页已显示全部系统正常。
- 已落地四项措施：**暂停同类维护**（另行通知前）、调整配置以降低连接抖动、增加可按比例**摘流**的功能开关、并验证了"100% 流量走主库"这一假设。后续计划包括维护前评审流程、维护期保留热备缓冲容量、副本延迟的快速恢复自动化，以及移除该失效模式的架构改造。
- 值得注意时间点：这一周 Anthropic、Google、微软都在争"更适合企业"的位置，而 ChatGPT 与 API 同时倒下 3.5 小时，等于给"单一供应商栈"做了一次公开演示。OpenAI 自己的措辞是："这一量级的故障尤其具有破坏性，我们这次没有做到。"

### 4. OpenAI 模型改写 AMD 旗舰 GPU 电路：最高 14% PPA，部分改动已随设计送厂
- OpenAI 在 **11 月 18 日**的技术报告中披露，其模型直接改写了 AMD 部分 **SystemVerilog RTL** 代码——即定义电路如何完成计算、控制与数据传输的那一层；改写后由 **Synopsys** 工具做功能验证，确认电路行为未变。中文媒体自 11 月 21 日起密集跟进。
- 成绩是**最高 14% 的 PPA（功耗、性能、面积）提升**，且对标的是"**已被高度优化**"的基线，而非粗糙起点。OpenAI 称这段合作把原本约**一年**的工程优化量压缩到**不足 5 个月**，并把模型在 RTL 层的推理能力形容为"**专家级微架构师**"水平。
- 落地进度：AMD 已将部分改动整合进**近期送厂制造**的芯片设计，其余进入面向未来产品的量产设计文件；范围不止 GPU，AMD 还用模型产出的设计在**下一代旗舰 CPU** 的关键模块上验证出**个位数百分比**的 PPA 提升。
- 同一套方法先在 OpenAI 与博通合作的自研推理芯片 **Jalapeño** 上跑通：一个乘法器重设计后综合面积减小约 **15%**、单次运算从 **2 个时钟周期压到 1 个**；向量单元标准单元面积省约 **13%**，矩阵单元约 **10%**，且在硅片点亮时验证过。
- 三个必须保留的限定：**14% 是 PPA 层面的收益，不等于 GPU 实际性能提升 14%**，功耗、性能、面积各自贡献 OpenAI 未拆分；**所有数字均出自 OpenAI**，AMD 没有发布自己的数据，也没有在报告中给出表态；具体哪些产品采用、是否对应 RDNA5/CDNA5/Zen6，**均无官方说法**。

### 5. NBER：提交量 +240%，发布只 +30%——AI 写代码的瓶颈挪到了评审台
- NBER 工作论文 **35275《Writing Code vs. Shipping Code》**（Mert Demirer / Leon Musolff / Liyuan Yang，2026 年 5 月首发、9 月修订）这个周末在 X 上二次发酵。研究把 **50 余万名 GitHub 开发者**的公开活动与微软内部的 Copilot 使用数据对齐，按三代工具分组：自动补全、同步智能体、异步智能体。
- 沿生产链往下，增益单调衰减：周提交量累计 **+30%（补全）/ +180%（加同步智能体）/ +240%（加异步智能体）**；到项目数只剩 **+80%**，到**发布版本只剩 +30%**。同步智能体单独看，代码行数 **+958%**、PR **+86%**，而发布只有 **+20%**。
- 另一个指标更能说明行为变化：采用同步智能体后，新增代码行是原来的 **7.0 倍**，删除行是 **12.2 倍**，新建分支 **+79%**；新建仓库"**首月后无活动**"的比例从 2021 年的 **60%** 升到 2026 年的 **69%**。App Store、Google Play、Chrome 插件商店与 SourceForge 自 2025 年初起月新上架量平均**翻倍**，但这四家新应用的**总体使用量都没有上升**；2026 年一次发布的代码中位数是 **13420 行**，2021 年为 5210 行。
- 作者用"**弱链（weak link）**"解释：人与 AI 的替代弹性只有 **0.23**，写代码提速之后，评审、测试、发布这些仍需人力的环节成为限速环节。他们也提醒，被放弃的代码不一定是坏代码——开发者可能只是在多试几版、留最好的那版，而且这一落差**不能**用"提交质量更低"或"AI 代码更啰嗦"来解释。
- 论文边界要写清楚：**未经同行评审**，样本限于开源社区与四个应用商店，关键数据来自微软，作者已披露潜在利益关系。但方向与同期多项独立证据一致——Harvard/Jellyfish 的 **65.5 万**员工样本（代码行 +44%、PR 合并等待时间 +56%）、Faros 对 2.2 万开发者的遥测（部署频次反降）、METR 的随机对照实验（开发者自认快 24%、实测慢 19%）都指向"上游提速、下游拥堵"。

## 四、政策与安全

- **OpenRouter 的处置本身就是一份监管样本**：不点名、摘牌 3 家、移除 125 个端点的 ZDR 资格、通知客户，并要求"想留在平台上的厂商必须达到更高标准"。Hacker News 上的主要批评是"为什么不点名"——这也暴露了路由层在 ZDR 上只能做"分类 + 信任"，无法做技术证明。
- **谷歌 Agent Compute Engine**（11 月 22 日经 InfoQ 等报道）：把代理放进隔离 **microVM** 运行，支持检查点挂起与恢复；核心是边界划分——**API key、OAuth 刷新令牌不进入沙箱**，留在外部 **Agent Gateway**，由其认证后再注入。编排 harness 完全跑在沙箱外、只向沙箱下发明确指令，形成"每次工具调用 ↔ 沙箱内计算活动"的确定性审计链。配套治理栈包括 Agent Gateway（流量与策略）、Agent Registry（已批准代理与工具）、基于 **SPIFFE** 的 Agent Identity 与兼容 **OpenTelemetry** 的可观测性。谷歌内部已用于 **Gemini、Gemini for Business、Antigravity** 与模型评估；服务尚未上线，计划数月内预览，**未公布定价**，仅限 Google Cloud。
- **斯坦福 + 东北大学 Shepherd**：把智能体的每个动作、状态与环境存成受版本控制的**提交**，让"回滚"获得与代码仓库相同的语义；meta 智能体可拦截动作、撤销或升级给人类，所有对外动作先落沙箱、确认后执行。论文计划 12 月投 NeurIPS，定位是"**治理代码**"而非更好的提示词。
- **美国 GAO 隐蔽测试报告**（GAO-27-108814，11 月 18 日公开）：调查人员以普通用户身份、用常见绕过手法，让 **ChatGPT、Claude、Gemini、Grok** 在 **12 小时内**各自产出被判定"可行"的攻击方案——两家给出针对大型城市人口密集场所的简易爆炸装置方案，两家给出针对变电站的方案（一为无人机、一为枪械）。四家平台的护栏**都先触发了，又都被绕过**；报告**未提出任何建议**，每平台仅测一个场景、无对照组，厂商方指出测试用的是旧版本模型。参议员 **Maggie Hassan** 称将以此在明年初推动听证与立法。
- **Meta Muse**：安全公司 **NebuSec** 11 月 20 日公开一条链式攻击——让 Muse 导出一个攻击者控制的网页，借内嵌 **Chromium** 的缺陷进入容器，再以自动生成的 **Linux 内核**利用（测试成功率超 **99.9%**）拿到用户云虚拟机的 root，从而读到对话历史、存储记忆与连接账号凭据，全程**没有弹出审批提示**，还能改写既有记忆。Muse 的 **Sentinel** 网络管控与独立凭据库按设计各自生效，但链条逐一穿过；未越出单用户 VM、未触及共享宿主。NebuSec 称全部漏洞在发布前已修复，Meta 未公开确认。
- **国家网信办**：11 月 20 日就《实施网络安全标识的产品目录（第二批）》公开征求意见（截止 **12 月 20 日**），纳入**消费类智能门锁、智能音箱、儿童智能手表**三类产品，同步征求意见三份实施规则；网络安全能力分**基础级 / 增强级 / 领先级**，对应**一星 / 二星 / 三星**标识，标识须载明生产者名称、型号、能力等级、有效期、检测实验室、依据标准与备案码。
- **中央网信办"清朗"专项行动**：据《经济日报》11 月 21 日评论，近期重点整治**滥用 AI 生成健康科普谣言**——伪造虚假权威通报、专家音视频，再借机带货牟利；评论提出的方向是划定 AI 使用红线、强化平台审核。
- **谷歌员工请愿**：据 Mother Jones 报道，数百名谷歌员工（Alphabet Workers Union，代表 1000 余人）联名要求撤回一项政策——从明年起，对关闭 Gemini 的学校**切断 Google Search**。请愿信称这"更可能导致学校把谷歌产品整体换掉"，已有三个大型美国学区在讨论替代搜索引擎。该政策于 11 月 3 日公布。

## 五、研究与测评速览

- **MedChemBench 把"读分子"和"选分子"拆开**：OpenAI 这套基准含 **99 道**药物化学题，取自 **117 篇**论文与专利、涉及 **761 个**分子，测了 11 个 GPT 模型。**GPT-6.2 Astra** 拿到可用分的 **84.5%**、读结构 **95.4%**，但"**下一步该测哪个化合物**"只有约**一半**正确。OpenAI 明确写道，这**不能说明模型会做药物发现**——差距恰好落在判断而非知识上。
- **芯片设计侧的对照实验**：在与 AMD 项目分开的 **RISC-V** 测试中，**GPT-6.2 Astra、GPT-6 Astra、GPT-6.1 Sol、GPT-5.6 Sol** 等模型从规格直接设计，每条约 **11.2 万 token**，全部高于基线；这也是"从规格出发"与"在既有 RTL 上改写"两种任务难度的分水岭。
- **伯克利 SuperMimic（CoRL 2026）**：引入**可微世界模型**后，单张 GPU 训练约 **3 小时**，在特定人形机器人动作跟踪基准上超过用 **128 张 GPU、训练 7 天**的对照模型，GPU 小时数不足千分之一，已在宇树 **G1** 上完成部分动作真机迁移；世界模型推演速度称达 MuJoCo Warp 的 **10 倍以上、最高 62 倍**（团队口径）。
- **智元 LIFE 与具身 RSI**：智元的终身具身智能框架 **LIFE** 在 FindingDory 测试的 **597 个**未参与能力构建的查询上，成功率从 **37.5% 升至 65.8%**；大晓机器人在酒店洗衣场景用约 **57 小时**完成 **165 轮**真机实验、形成约 **80 个**版本，牛仔裤留在烘干机筒内的比例从平均 **48% 降至 32%**。
- **榜单与价格同步改写**：**Gemini 4 Neon** 进入 Artificial Analysis 前三，定价 3/15 美元每百万 token；**GPT-6.2 Astra** 相对 GPT-6 Astra **降价 20%**（$8 / $0.40 cached / $40），OpenAI 称其在长周期专业工作测试 **Agents' Last Exam** 上高出 **5.2 分**、成本不到三分之一；**Sol** 在 Cognition 的 **FrontierCode 2.0** 上仅落后 Astra **0.5 分**、成本约为其五分之一。早期测试者反馈 Astra 存在**循环**与**输出无法解析**的问题。
- **自我改进的账本**：**ELITE** 把初始编码智能体在 **SWE-bench Pro** 上从 **60.0%** 提到 **85.6%**，**AIDE²** 自主运行八天找到七次改进；但 **RSI Tax** 论文测得验证环节占三种自改进方法**聚合 token 成本的 74.8%—93.6%**——裁判始终站在闭环之外。

## 六、一句话观察

> 11 月 22 日这天的新闻，几乎没有一条在讲"模型更强了"。OpenRouter 摘牌三家厂商、125 个端点失去零留存，是在说**你以为的隐私承诺只约束了第一跳**；OpenAI 用 211 分钟证明，两个"冗余"副本可以同时失效，而承重的那一层恰好是全站认证；微软把 Sol 铺给所有人、把 Astra 关进 Frontier，是在用价签做能力分层；NBER 的 50 万开发者数据更直白——**提交涨 240%，发布只涨 30%**。唯一真正往前推的一步，是 OpenAI 的模型在 AMD 已高度优化的 RTL 上抠出 14% PPA 并把改动送进了流片：它不是"生成得更多"，而是**生成之后有人能验、验完敢用**。三条线合起来指向同一个转折：AI 的稀缺资源已经从"生成能力"变成"**验证带宽**"与"**责任归属**"——这也解释了为什么同一天谷歌在把密钥挪出沙箱、斯坦福在给智能体装撤销键、AWS 在给每个子代理发最小权限票据。下一轮预算不会投给最会生成的那一方，而会投给能把"可核验的交付"规模化的那一方。
